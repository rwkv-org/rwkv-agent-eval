## 验证与汇总

- 结论数量：**OK 0，已修 18，已删 0，有风险 0**；保留全部 18 题，未发现需要删除的事实错误或不可消解的题面歧义。
- 每次修改题目后均单独运行 `python3 bank/check_own.py bank/own/cases/<id>.json`；最终整批再检为 **18/18 通过**，参考答案通过、空回复且无工具调用不通过。
- 另做 **135 项核验**：每题 3 种合理中英文搜索词，共 54 条，全部至少命中一个现有 `--match`；其余覆盖合理答案变体、典型错误答案、复用前轮证据和首轮无搜索调用的失败情形。
- 新增 **15 个官方页面存档**，原搜索记录与原页面均保留；所有题的关键证据均可在正文前 15,000 字符内找到，全部声明页面返回 2xx；补抓只通过 `bank/web_tool.py` 完成。
- 本批没有本地输入文件、文件修改任务、受保护测试或参考代码修复，Debian/BSD 命令兼容性审查不适用；没有实际运行 Debian 容器。没有 `output_excludes` 或 `expected_number`，不存在相应的旧值误伤或默认 40 字符限制。
- 最常见的问题是搜索结果已有官方链接却没有正文存档（12 题原先完全没有页面）、数字及许可证合理别名覆盖不足、多轮强制重复搜索，以及多个宽泛关键词无法验证同一个完整 API 名称。
- 固有局限：开源项目的公司、年份、许可证和默认端口属于公开事实，尤其 Google、MIT 等答案可能凭记忆得出；首轮强制 `web_search` 可阻止纯无工具作答，但现有判分器不能证明模型真正阅读了结果，也不能全面理解否定句或“罗列所有候选答案”的语义。此次已修复定位到的具体误杀和误放，未修改范围外的判分器或改换本批题材。
