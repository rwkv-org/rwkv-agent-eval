本批 17 题均逐题对照 adapter 两次与 base 两次的 steps、judge 和最终回答，并核对了 5 道旧题的完整多轮要求及关键本地文档、配置和程序判据。
主因分布：doc-apply 6 题、cmd-error 5 题、spec-miss 3 题，其余 protect-violate、no-verify-fabricate、knowledge 各 1 题；最常见的是“读到规则但没有正确落地”和“精确编辑失败后无法恢复”。
文档应用应重点补特殊值、默认行为和多分支对照：不存在的数据库名返回 -1、If-Match 星号检查存在性、隐含 text/html、完整 socket 路径预算，而非只背 API 名称。
精确编辑应补“原始正文与 read/repr 展示层分离 → 按真实路径、空格和缩进构造替换 → not found 后回读修正 → 核对最终文件”的目标轨迹，尤其覆盖隐藏文件、INI、YAML 和 XML。
约束执行应补“只答标识、不附解释”“仅改指定字段、参考文件保持不变”和“首轮只读、后轮实际写入”的样本；SQL 与 SQLite 匹配题尤其接近完成，不能误判成不懂单位或返回码。
交付核对应补“源码实际编辑 → 文档完整来源落盘 → 对照变更清单检查 → 据工具结果报告”，避免只贴代码、写错文件、误改策略文件以及工具失败后声称成功。
base 多题停在伪工具调用文本或猜测本地文档路径；adapter 已改善真实抓取与文件读取，新增数据应侧重抓取之后的提取、应用、范围控制及一次有效恢复，而非泛化增加搜索步骤。
near_miss 按 adapter 中最接近完成的一次评估，共 10 题，仅表示剩余问题可局部修正，不表示两次都接近；所有 trial 的 exc 均为空，现有证据不足以归为思考超时或步数耗尽。
