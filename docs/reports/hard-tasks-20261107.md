# 两边都 0 分的难题分析：下一轮补数据的直接依据（2026-11-07）

对象：基模 `rwkv7-g1l-7.2b-20261031-ctx34304` 和 adapter `g1l-nora-r16-lr2e-5-e2` 在 1019 题上（每题各 2 次）**四次全错**的题。
修正一处判据后共 **327 题**（第一版题 121 + 第二轮新题 206；留出 313、开源 10、已训回测 4）。

方法：
1. `runner/hard_digest.py` 在服务器上把每题的题面、判据、四次 trial 的工具调用序列、判分信息、思考量和最终回答压成摘要（`runs/hard/digest.jsonl`，不入库）。
2. 17 个 Codex（gpt-6.1-sol）分批逐题诊断，用固定的 16 个归因代码，每题给出主因/次因、是否差一点、人类难度、缺的能力、能教会它的目标轨迹和证据。提示词和每批小结在 `build/codex-hard/`；逐题结果在 `docs/reports/hard-tasks-20261107-tasks.jsonl`。
3. 我从每类主因各抽 1 题对照原始轨迹核对（6/6 吻合），并用 trace 做了机械统计（重复调用保护、edit 失败、超时、声称完成）。

## 结论（先看这里）

1. **这些题难在模型的习惯，题本身并不难。** Codex 按“称职工程师用同样的工具”来估，327 题里 easy 243、medium 84、hard 1；有 96 题是“差一个细节”（排序、表头、只答标识、一个边界）。所以这批题适合留在题库里，当作补数据效果的直接验收集，不建议换成更简单的题。
2. **最大的单一问题在插件，不在数据：重复调用保护拦了合理的核对。** 全 0 题里，adapter 被保护拦下的重复调用中，**472 次是改过文件之后的核对**（354 次重读改过的文件，118 次用同一条命令重跑测试）；真正原地打转（中间没有任何修改）的是 263 次。被拦之后，adapter 有 168 次 trial 以模板话收尾（“没能整理成答案”），集中在代码修复、网页+代码、终端三块。基模被拦的几乎全是原地打转。也就是说，adapter 学会了“改完要验证”，验证动作却被插件当成重复调用拦掉了。
3. **数据层面，排在前三的缺口都出在“动手之后”**，而不是“该不该调工具”：
   - **精确编辑和失败后的恢复**：121 题。edit 的 old_string 是凭记忆拼的，匹配不上之后不会重读原文、缩小替换范围（656 次 trial 里 125 次出现过 edit 未命中，其中 92 次之后再也没有成功写入过）。
   - **命令/统计口径写错却没发现**：92 题。数错列号、awk 跳过首行、CSV 硬拆逗号、正则写错，命令“执行成功”，结果却是错的。
   - **没核对就交差，或者编造结果**：87 题。测试还没过就说“已修复”（69 次 trial），工具报错后硬编一个结果写进文件。
4. **多轮是新的薄弱点**：327 题里 157 道是多轮题，其中 48 题 adapter 首轮已经通过，之后的轮次却挂了：沿用了旧结论、漏了新约束，或者第二轮不再调用前一轮已修好的函数。
5. **之前报告里的 P0/P1 继续成立，但优先级要调整**：“改完后的收尾”应该先改插件（见下文“插件侧”），数据只需补“被拦之后怎么收尾”；“精确编辑恢复”“结构化统计”“凭证据交付”这三类应升为 P0。

## 4. 插件侧（不靠数据解决，需要评测和训练环境一起改）

1. **重复调用保护在文件被修改后要重置。** `dsh-rwkv-plugin/src/core/agent.ts` 的 `gateToolCall` 用 `callKey(工具名, 参数)` 查 `successKeys`，文件被 edit/write 改过之后键不会失效。建议任何一次成功的 edit/write/bash 之后，清掉 read 类和 bash 类的 successKeys（或只清涉及改过路径的那部分）。这是上面 472 次被拦的直接原因；训练数据里有 290 条“改完再读”的目标步，这样改了之后训练和评测的行为才一致。
2. **当前时间**：插件在 `src/history.ts` 的 `RUNTIME_CONTEXT_KEPT` 白名单里只保留了工作目录和沙箱策略，DSH 的其他 runtime-context 段（包括时间）都被丢掉了。放开时要能固定评测时间（例如用网页存档的抓取日期），训练数据也要用新插件重新生成。
3. 以上两项都会改变模型看到的上下文，下一轮训练数据要用改过的插件生成，评测也换同一个插件版本。

## 5. 判据问题

**已修（本次提交）**：own-wc-073/078/083/087/090 第 2 轮题面要求“只新增结果文件 reports/xxx.json”，判据里却误加了 `unchanged_files`。按 SPEC，这个字段表示只读轮，结果是用 write 新建文件就判 0。已从题目源（`bank/own/cases`）和 build 副本（本地和服务器）中删掉，`runner/rescore.py` 增加了对应的重判规则。影响：只有 own-wc-073 的 adapter 两次从 0 变成满分（这一轮唯一的错误就是这一条），总分 52.85 → 52.94，其余 4 题另有真实的测试失败。全 0 题因此从 328 变为 327。
